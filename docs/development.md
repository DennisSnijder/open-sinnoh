# Development tools

## Developer tools overlay

On the dev server, add `?debug=1` (or `&debug=1` after other URL options) to show the plain **Developer
tools** overlay. It can warp to a map/tile, read/set/clear flags and vars, give items and Pokémon (PC
overflow), and freeze the clock. Mutations require an idle field. Reset flag/clear var restores the registry
default. Script-local temporary vars cannot be edited through GameState. A clock override lasts until a new
game/reset.

The checkpoint selector lists each story chunk's chain anchor (seeds 1–3), looked up in this checkout's ROM
test cache under the same key the ROM checkpoint tests use (`tests/integration/anchor-key.ts`). Loading one
the cache does not hold fails with the file it expected; run the ROM checkpoint tests to make it, then refresh
the selector. Loading replaces the current session state and freezes its saved clock; the normal save
validator rejects incompatible packs. Nothing is replayed or generated by the overlay. These caches are local,
ROM-derived and gitignored. The overlay and its CSS are excluded from production bundles; the cache endpoint
exists only on the dev server.

## Flaky tests

```sh
pnpm flaky packages/core/src/clock.test.ts --runs 20
pnpm flaky tests/browser/app-shell.spec.ts --runs 10 --cpu-load 2 -- --project desktop
pnpm flaky 'test title' --runner playwright --runs 10
pnpm flaky path/to/file.test.ts --grep 'test title' --runs 20
```

`flaky` selects Playwright for `.spec.ts` paths and Vitest for `.test.ts` paths or bare test names;
`--runner` overrides this. It starts a fresh runner for each iteration (10 by default), disables retries, and
reports the share of iterations that passed and the first failure for each distinct error, with its test and
occurrence count. A skipped-only or empty selection fails. Runner options follow `--`; use `--grep` to select
a title within a file. Playwright runs one worker by default. `--cpu-load N` adds N busy CPU worker threads to
emulate contention; these stop when the command exits or is interrupted. ROM tests still require
`OPENSINNOH_NDS_ROM`.

## Cleaning up git worktrees

```sh
pnpm clean:worktrees                         # dry run: lists what would be removed
pnpm clean:worktrees --apply                 # removes the merged worktrees it lists
pnpm clean:worktrees --stale-days 30 --apply # also unmerged branches idle for 30 days
```

`clean:worktrees` is a dry run unless `--apply` is given. It only considers registered git worktrees under
`.claude/worktrees/`; the main checkout and anything elsewhere are never touched. A worktree qualifies when
its HEAD is merged into local `main` (or `--base <ref>`), or, only with `--stale-days N`, when it is on an
unmerged branch with no file changes for N days. It is kept when it is locked, dirty or untracked, the current
worktree, reached through a symlink, holding a `.nds` file, on an unmerged detached HEAD, or written to (files
or `.opensinnoh-cache`) in the last 24 hours, since a test run may be using it. Removal is
`git worktree remove` without `--force`; branch refs are always kept. A missing checkout has only its own
registration removed. The plan is rechecked just before removal. Fetch first if you need the latest `main`.

## Other tools

`package.json` lists the rest: `pnpm perf` (performance budgets, `tools/perf-budgets.json`), `pnpm fixtures`
(rebuilds the original fixture pack), `pnpm brand:assets` (favicons, app icons, link cards and the README
wordmark from `packages/ui/src/brand.ts`), `pnpm viewer` (a model viewer), `pnpm sweep:browser` (renders every
zone of an imported pack).
