# Contracts

`packages/contracts` is the only cross-package surface. `packages/core` holds the game-agnostic pieces
(IDs, PRNG, JSON Patch, semver, script IR, replay grammar, pack loader). Change either only in
a reviewed step: bump `CONTRACTS_VERSION` and add a line below.

| Area | Where | Summary |
|---|---|---|
| IDs | core `ids.ts` | `namespace:NAME`. Base content uses `platinum:` and decomp names where they exist (`platinum:FLAG_HIDE_ROUTE_201_RIVAL`), otherwise `platinum:<kind>/<index>`. |
| Packs | core `packs.ts` | `pack.json` manifest, `PackData`, `RecordPatch` (RFC 6902), load order (base and dependencies required, loadAfter honoured). Later packs win. Disabling a pack means reloading without it. `cosmetic: true` packs touch only `sprites`/`followers` and are not part of a save's pack identity. |
| Assets | contracts `records.ts` | `AssetRef` = `<pack>:<path>` (a file in that pack). Models are glTF 2.0 + PNG, sprites are PNG atlases. |
| Registries | contracts `records.ts` | zones, matrices, chunks, areas, lights, weathers, fieldEffects, props, models, textureAnimations, cameras, sprites, movements, texts, flags, vars, species, moves, abilities, types, natures, growthRates, items, marts, trainers, fonts, newGame, titleScreens; plus encounters, tileBehaviors, textBanks; 2D art: ui2d, pokemonSprites, trainerSprites, battleBackgrounds, battleTerrains; battle data: aiScripts, battleAnimations, particleSystems, battleAnimData. Event and player x/z are tile coordinates in the zone's matrix; y is in world units. |
| Pokémon | core `pokemon.ts`, `bag.ts`; contracts `state-edits.ts` | The instance model (`Pokemon`), Gen 4 rules from the decomp (stats, nature/gender/shininess from the PID, level and exp, moves and PP, EVs, evolution checks, the trainer-party PID derivation) over the data records (`Dex`). The bag (`Bag`, pockets from `NewGame.pockets`). Shared state edits: `giveItem`/`takeItem`, `markSeen`/`markCaught`, `setupPokemon` (replay `party` lines), `dexOf`. |
| Script IR | core `ir.ts` | Labels of `{op, args}`; args are int, string or `kind(Id)`. Ops are decomp command names in snake_case (`apply_movement`, `goto_if`). Var-or-value operands are resolved at import (≥ 0x4000 → `var(...)`). Message indexes become `text(...)` refs. |
| Names | – | Readable IDs come from a committed, names-only table generated from the decomp (`tools/names`): script entries (`platinum:TwinleafTownPlayerHouse2F_TV`), messages (`platinum:TwinleafTownPlayerHouse2F_Text_ItsAWii`), flags, vars, zones, species, items, movement actions. Internal branch targets are `platinum:<FileName>/off_<hex>`. Anything unnamed is `platinum:<kind>/<index>`. The override unit is the label. |
| IR ops | – | One IR op per native script command. Op = the decomp command name (`ScrCmd_*` / macro-table name) split at CamelCase and lower-cased: `GoToIf` → `go_to_if`, `SetVarFromValue` → `set_var_from_value`, `StartChooseStarterScene` → `start_choose_starter_scene`. Macros such as `GoToIfEq` are not ops; they appear as their expansion (`compare_var_to_value` + `go_to_if "eq"`). Conditions are strings `lt eq gt le ge ne`. Object args are local ids (`LOCALID_PLAYER` 255, camera 0xF1, follower 0xF2). `call_common_script` runs a concurrent sub-context with its own text bank; it is not a plain `call`. |
| Movements | – | Steps are decomp `MOVEMENT_ACTION_*` names, lower-cased without the prefix (`walk_normal_north`). |
| Text | contracts `text.ts` | OpenSinnoh markup (`{var N}`, `{clear}`, `{scroll}`, `{color N}`, …); parser and printer round-trip. |
| Field seam | contracts `field.ts` | `FieldHost` (world services for the VM), `ScriptRunner` (VM for the world and the loop), `ScriptView` (message, yes/no and panel, owned by the VM). Tick order, trigger priority and map-load order are documented at the top of `field.ts`. The VM and world share one mutable `GameState`. `ScriptView` also carries `menu` and the signpost kind; `FieldView` carries `doors`, `area`, actor `pose`, `weather`, `darkness`, `effects` and `cameraOffset`. FieldHost has `setWeather`, `moveCamera`, `shakeObject`, `elevator`, the HM tasks `surf`/`waterfall`/`rockClimb` (each waited on with its `…Done`), `releaseObject`, `forceBicycling`, `setPlayerHeightCalculation`, `setBgEventPosition` and the platform lift (`initPlatformLift`, `platformLiftNotUsedWhenEntered`, `triggerPlatformLift`/`platformLiftDone`). FieldView also carries `elevatorLights` and `platformLift`; ScriptView `floorWindow`. |
| TS scripts | – | Deferred (see `docs/decisions.md`). The v0.1 demo mod overrides an IR label. |
| UI | contracts `ui.ts` | Single screen: the field fills the screen. The `panel` (256×192 logical) is an overlay card shown only with content. `InputFrame` (held, pressed, touch, optional `screen: 'main'`), `PanelView`, `choiceRects`/`hitChoice`, `menuRects`/`hitMenu`. The start menu and Pokétch are app UI (`packages/app/src/ui`) over `GameState`, not contract surfaces. |
| Menu apps | contracts `apps.ts` | Headless models (packages/menus `createApp`) the game hosts next to the VM: `AppRequest` (start menu; `mart {mart, countVar, greeting}`), `AppResult`, `AppModel` (`step(InputFrame) → result \| null`, `view()`), `AppHost` (device options, save), `AppView` (one view per app; strings are plain text; tap ids per view). `InputFrame.tap` is a tap on the open app. The app's DOM draws only `AppView`. |
| Saves | contracts `state.ts` | `GameState` (schema v23: the TV (`tv`) and the gallery photos (`dressUpPhotos`); v22: the Seal Case (`sealCase`) and the journal (`journal`); v21: the Underground's laid traps and secret base (`underground.placedTraps`, `underground.base`); v20: the contest photos (`contestPhotos`); schema v15: the roamers (`roamers`: slots, route indexes, the player's recent zones); v14: the map features slot (`mapFeatures`, contracts `gyms.ts`); v13: game record counts (`records.counts`, by RECORD id); v12: the Pokétch's `PoketchState`; v11: Pokédex `forms` (seen forms and genders), Pokémon `markings` and `ribbons`; v10: `daycare`; v9 unused; v8: `gameTime`; v7: start date, play time, coins, registered item, unlocked wallpapers, Repel steps, game records, signature, saved options; v6: `previousZone`, `platformLift`; v5: real `party`, `boxes`/`currentBox`, `bag`, `trainerId`, Pokédex `seen`/`caught`; v1–v12 migrate) and `SaveEnvelope`. A save is allowed only when no script runs and the world is idle; otherwise it throws. |
| Battles | contracts `battle.ts` | Draft (M2 step 0). `CreateBattle(setup, deps) → Battle` (`step(input)`, `choose(choice)`, `view(): BattleView`, `done(): BattleResult \| null`). `BattleSetup` {kind, trainers, wild (species, level), background, terrain, time}; `BattleResult` {outcome = decomp BATTLE_RESULT_*, turns, party}. The game runs battle mode: the field and VM do not tick, nothing is saved, the result's party replaces the state's. `FieldHost.startBattle`/`battleDone`; `CreateWorld` deps gain `battles`. |
| Audio | contracts `audio.ts` | Draft (M4). `AudioHost` (the game's deterministic sound system: BGM, fades, SEs, fanfares with `waitFanfare`, cries with `CryMod`) for the VM, game and apps; `AudioOutput`/`AudioCommand` (output only, per NNS handle). Records `sequences`, `soundBanks`, `waveArchives`, `soundPlayers`, `cries`; `soundFramesToTicks`. |
| Runtime wiring | contracts `runtime.ts` | `CreateWorld`, `CreateScriptRunner`, `MountFieldRenderer`, `DrawScriptOverlay`, `AssetSource`, `StubLog`, typed `Registries`. |
| Bridge | contracts `bridge.ts` | `window.openSinnohGame` for replays and automation; `useFieldMove`, `usableFieldMoves`, `setClock(date?, time?)`. |
| Replays | core `replay.ts` | `<tick> <action>` or `+N <action>` (30 Hz ticks); waits `until idle|message|yesno|menu|choice [max]`, `until position <x> <z> [max]` (x or z may be `{path}` or `{path|k=v,…}`, a number read from GameState when the step runs — what the player can see, e.g. Hearthome's correct door; loud when missing or unmapped), `until state <json-path> <json> [max]`, `until wild <species> [<dir> <dir>] [max]` (a field wild battle against that species is up; with directions it walks like `grind` and runs from the others) and `advance text [max]` (A on every waiting message until a choice or idle), each ≥ 1 tick, failing at `max`; `from <replay>`; setup lines before tick 0 (`set flag|var`, `give item|badge`, `party`, `warp <zone> <x> <z> [facing]` (the state then loads as an arrival, 0.28.4), `player walk|cycle [0|1]`, `event <name>` (a dev-only event, 0.28.1), `date <yyyy-mm-dd> [hh:mm]`, `time <hh:mm>`; both also as timed actions that step the frozen clock); the actions `field move <slot> <move>` and `reload` (save → load now); press/release (12 buttons), touch/untouch, screenshot, viewport; asserts `map`, `position <zone> <x> <z>`, `facing`, `flag`, `var`, `party`, `message`, `text <json string>` (the message box's text), the generic `state <json-path> <json>` (GameState and `battles`; `[field=value]` picks an array element), and the battle log by content: `battle <kind> <id|*> <result>`, `battles <kind> <n>`. |

## Time
- Fixed 30 Hz simulation tick (the decomp main loop runs game logic every second vblank). Text
  printing advances 2 sub-steps per tick. Rendering interpolates and never moves simulation time.
- Seeded PRNG in the state. No `Math.random` or wall clock in game logic.
- The game clock (the DS RTC, core `ClockTime`) comes only from the game's clock source: the device's
  local time in play, frozen at core `DEFAULT_CLOCK` (2009-03-22 12:00) in headless runs, tests and
  replays, stepped by `date`/`time` lines. Periods are core `dayPeriod(hour)` (decomp TimeOfDayForHour).
