Research, 2026-10-15, with presentation implementation notes added 2026-10-18. Primary source: pret/pokeplatinum at **`1dc13dcea40c04ab53f1f607de46023dc409ef20`**. All decomp links below pin that revision. This is an independently worded behavioral specification: no implementation code, dialogue, staff names, art, ROM bytes, saves or screenshots are reproduced. The initial research did not include a gameplay run; the later visual reference is identified in §6. “Proposed” identifies engine design, rather than a claim about the original game. Read with [the checkpoint rules](../testing.md), [the credits card](../scope.md) and [story CP19](story-cp5-19.md#19-cynthia--hall-of-fame--save--credits).

## 1. Timing convention

The normal application/task loop is nominally **30 Hz**: after running the application and main tasks, it waits for a VBlank if none has occurred and then waits for another VBlank; fades, sound ticks and the application VBlank callback run once per loop. The IRQ's separate `vBlankTaskMgr` executes every hardware VBlank (nominally 60 Hz). Therefore a main-task delay of 20 means 20 frames at 30 Hz, but a 28-step movement explicitly scheduled with `SysTask_ExecuteOnVBlank` means **14 frames at 30 Hz**. Below `f` means 30 Hz frames, and VBlank steps are identified separately. State changes, completion polling and post-VBlank cleanup add frame boundaries; component durations are not a claim of one exact total cutscene length. [src/main.c:121–160](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/main.c#L121-L160); [src/system.c:35–40](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/system.c#L35-L40); [HoF scheduler:605–608](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/cutscenes/hall_of_fame.c#L605-L608).

## 2. Script and ClearGame: exact sequence

The field script queries **saved Hall of Fame history**, rather than the completion flag, to select first/repeat presentation. After the approach scene it sets `FLAG_UNLOCKED_VS_SEEKER_LVL_4`; enables hidden Spring Path if the National Dex is enabled; changes `VAR_DUMMY_0x40F4` from 0 to 1 only; obtains the full party count; runs the Hall of Fame machine animation; fades out; increments the Hall of Fame trainer-score event; runs the victory flags/vars helper; and calls `ClearGame`. Its later `ReturnToField`/fade/release tail is unreachable in the ordinary reset path. [field script:10–70](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/res/field/scripts/scripts_pokemon_league_hall_of_fame.s#L10-L70).

The machine animation is **before Champion ribbons and before the actual party heal**. It places a miniature ball for every party slot (the caller does not exclude Eggs), top left/right, middle left/right, bottom left/right. Each ball has a wait counter capped at 15; the add/wait states introduce additional frame boundaries, so this is not exactly 15f per ball. It then plays the shared ball-prop animation, waits for its loop completion and removes the props. This routine changes props, not HP, status or PP. No explicit healing jingle is requested by this routine: it invokes the prop animation API without its sound-effect variant; an animation-data-dependent sound has not been established. Its final animation length depends on imported prop animation data; no fixed total is established here. [healing animation:31–38,69–144](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/overlay006/healing_machine_animation/hall_of_fame.c#L31-L144); [15-tick constant](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/include/overlay006/healing_machine_animation.h#L10-L18); [VM wrapper](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/scrcmd.c#L5689-L5695).

The victory helper does the following, **also on repeat clears**:

- Clears `FLAG_HIDE_DAY_CARE_GYM_GUIDE` and `FLAG_ALT_MUSIC_CHAMPION_ROOM`.
- Resets `VAR_SPEAR_PILLAR_DIALGA_STATE` / `…PALKIA_STATE` to 0 if the corresponding Pokémon is not caught.
- If Heatran is uncaught and `FLAG_TALKED_TO_BATTLEGROUND_BUCK` is set, clears its room-3 hide flag and sets `VAR_STARK_MOUNTAIN_ROOM_3_STATE` to 1. If Regigigas is uncaught and the National Dex is enabled, clears its B5F hide flag.
- Clears the Azelf, Uxie and Turnback Cave Giratina hide flags when each is uncaught.
- For each **defeated** roamer, changes its state to `ROAMER_STATE_RESET`: Mesprit and Cresselia also have their origin hide flag cleared; the three birds only have their state changed.
- Changes `VAR_PLAYER_HOUSE_POSTGAME_STATE` from 0 to 1 only; clears `FLAG_HIDE_SANDGEM_TOWN_COUNTERPART`; unhides the Veilstone B1F professor unless already talked to; unhides Canalave library Lucian; clears `FLAG_TALKED_TO_CELESTIC_TOWN_CAVE_CYNTHIA`; sets `FLAG_HIDE_SENDOFF_SPRING_CYNTHIA`.

Source for all conditions and writes: [field script:123–208](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/res/field/scripts/scripts_pokemon_league_hall_of_fame.s#L123-L208). Cynthia's victory and `FLAG_DEFEATED_CYNTHIA` precede this room; that flag is not set by `ClearGame` itself. [Champion script:44–81](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/res/field/scripts/scripts_pokemon_league_champion_room.s#L44-L81).

`ScrCmd_ClearGame` installs a field task. Initialization, before showing the record presentation, is ordered as follows:

1. Capture **prior** `FLAG_GAME_COMPLETED` twice: for deciding whether to reset loaded history and whether credits may be skipped. Capture trainer, party, play time, gender and Pokédex references.
2. If not previously completed, record the first-completion RTC timestamp.
3. Give Champion ribbons to party members that are not Eggs.
4. Set the special continuation location to the player's Twinleaf upstairs room, local `(4,6)`, facing up; set the exit/first-respawn location to Twinleaf, global `(116,886)`, facing down.
5. Enable Communication Club access; set `FLAG_GAME_COMPLETED`; mark trainer main story cleared.
6. Increment `RECORD_TIMES_ENTERED_HALL_OF_FAME`, then start the sequence task.

The task order is **record presentation → save screen → actual heal + main save + separate history save → credits → clean reset**:

| State | Behavior |
|---|---|
| 0–1 | Launch the Champion Hall of Fame application; wait until it closes. Recreate save-screen resources and fade the main screen in over 8f. |
| 2 | Check overwrite conflict. Normal case starts save-status printing; conflict jumps directly to state 7. |
| 3–4 | Wait for printing; heal all party members; require a full save; call `SaveData_Save`; load/update/write the separate Hall of Fame block; clear busy UI; print the main-save result. |
| 5–6 | Wait for result printing; play `SEQ_SE_DP_SAVE_sseq`; wait counter 18f before advancing. |
| 7–8 | Fade out over 8f; remove save-screen resources; start credits using the captured **prior** completion value. |
| 9 | Wait for credits app completion; free resources; `OS_ResetSystem(RESET_CLEAN)`. |

[task:88–169](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/clear_game.c#L88-L169); [result UI:290–305](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/clear_game.c#L290-L305). The save sound does not prove a successful write: the result UI uses the main save's return value, while the task still continues to credits/reset.

**Separate history block and conflict branch.** Hall of Fame is an *extra* save entry with its own read/write functions, outside the ordinary save table. After the main save, the helper loads it; reinitializes it if the load is not OK **or this is the first completion**; snapshots the current party and current date; then calls its separate save function. The main-save result does not gate this helper, and its write result is ignored. Thus main save and history are not one atomic transaction. [extra table and functions:113–131](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/savedata/save_table.c#L113-L131); [helper:69–85](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/clear_game.c#L69-L85).

`SaveData_OverwriteCheck` means **new-game data while a prior save exists**, not simply “there is already a Hall of Fame record” or “this is a second victory.” That conflict bypasses states 3–6: no actual party heal, no main save, no appended history, and no normal result/sound wait. In-memory ribbons, flags, locations and game-record changes have already happened; the record presentation, credits and reset still run. A normal repeat clear of the current save takes the ordinary save path. [overwrite predicate:246–249](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/savedata.c#L246-L249); [branch:108–163](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/clear_game.c#L108-L163).

**Reload.** On a successful normal save, the continuation path notices the Communication Club accessible flag, clears it in the loaded running state, and installs the saved special location before map initialization: **Twinleaf upstairs `(4,6)`, up**, not the Hall of Fame machine. The saved completion flag, trainer state, party ribbons, healed party, updated history and postgame variable survive their corresponding successful writes. The ordinary journal display may run before the map. Going downstairs later triggers the player's mother event and changes the postgame variable from 1 to 2; the immediate reload is not that downstairs event. After an overwrite conflict, reload shows the previous durable save, not the unsaved new completion. Main-save failure can leave a different history/main-save combination because the history write is still attempted. [continue task:491–540](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/field_map_change.c#L491-L540); [downstairs event:75–95](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/res/field/scripts/scripts_twinleaf_town_player_house_1f.s#L75-L95).

## 3. Hall of Fame data and the two applications

There is no single application with a record/view flag: the Champion runs `HallOfFameManager`, while the PC runs `PCHallOfFameManager`. The former reads the **live party** and trainer/play-time data; the actual history snapshot is appended later by the save task. The PC reads the separate saved history. [app launchers:1376–1408](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/unk_0203D1B8.c#L1376-L1408); [record initialization:307–324](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/cutscenes/hall_of_fame.c#L307-L324).

### Stored entry

The capacity is **30 entries × up to 6 non-Egg Pokémon**, a circular buffer with `nextEntryIndex` and `totalEntriesCount`. Each Pokémon stores species (`u16`), level and form (`u8`), personality and full OT ID (`u32`), nickname (11 UTF-16-sized game characters including terminator), OT name (8 including terminator), and four move IDs (`u16`); two padding bytes have no gameplay meaning. Each entry also stores year/month/day. No HP, PP, status, item, IVs, EVs, ribbon bitset, trainer play time or met location is stored here. Record mode can show met information because it still has the live party. Personality + OT ID + species/form support the correct gender, shiny palette and sprite variants when the PC reconstructs the display. [definitions:12–47](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/include/hall_of_fame_entries.h#L12-L47); [snapshot:25–90](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/hall_of_fame_entries.c#L25-L90); [PC sprite reconstruction:527–555](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/applications/pc_hall_of_fame/display.c#L527-L555).

Eggs are omitted and remaining members compacted in party order. The destination's six slots are cleared first; species zero terminates the stored party. At 9999 total entries, further additions stop entirely. Otherwise the next index wraps at 30 and the total increments; stored count is `min(total,30)`. UI entry index zero is newest; displayed entry number is `total − index`, and physical ring lookup is `next − 1 − index`, wrapped once. Consequently league victories may exceed 30 while only the last 30 teams remain. [writer:36–86](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/hall_of_fame_entries.c#L36-L86); [readers:93–181](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/hall_of_fame_entries.c#L93-L181).

### Champion record presentation

Main-screen presentation: fade from black; show each non-Egg member individually, alternating sides with a sliding window frame; play its front-sprite animation and species/form cry; reveal the introduction line, nickname/species/level/gender, then OT and met/hatched/traded-origin text; remove its text/frame and proceed. After the individuals, the player sprite rises from below while its frame descends, then its window expands, player name/low trainer ID/play time appear with a congratulatory heading, and party sprites enter from alternating sides. Spotlights run in the background; confetti becomes active once the final group arrives. **Only the final group screen accepts A or B** to continue; early A/B does not skip the individual sequence. The app then wipes inward to black and fades its music. [state order:385–572](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/cutscenes/hall_of_fame.c#L385-L572); [text construction:1278–1353](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/cutscenes/hall_of_fame.c#L1278-L1353); [player/group:1400–1485](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/cutscenes/hall_of_fame.c#L1400-L1485); [spotlights/confetti initialization:330–347](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/cutscenes/hall_of_fame.c#L330-L347).

### PC view presentation and script operations

The PC initially loads newest entry, member zero, general-text state. Its 2D screen shows the entry ordinal/date, all saved front sprites, and selected-member information. The selected sprite is opaque and in front; others are translucent. General text includes nickname, species, derived gender, level and OT name; A toggles a four-move panel (two columns). This does not replay the Champion animation, spotlights or confetti. No 3D camera is created by this viewer. [initial state:151–188](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/applications/pc_hall_of_fame/manager.c#L151-L188); [display:194–245](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/applications/pc_hall_of_fame/display.c#L194-L245); [text:369–436](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/applications/pc_hall_of_fame/display.c#L369-L436).

Inputs are edge-triggered: B closes, A toggles text, Left selects an older entry and Right a newer entry, both wrapping. Up/Down select the preceding/following member; crossing a team boundary moves to the adjacent entry (Up selects its last member, Down its first). Left/Right reset member index to zero. Input is blocked while a transition runs. Open/close fades are 6f; entry redraw runs four states; member highlighting and text toggles finish immediately on their transition calls. Selection and entry redraw play the selected species/form cry, explicitly using the default Chatot cry; A plays `SE_CONFIRM_sseq_3`; closing plays `SEQ_SE_DP_PC_LOGOFF_sseq`. No new music is started in the PC display routine. [controls and wrap:54–148](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/applications/pc_hall_of_fame/manager.c#L54-L148); [transitions:154–245](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/applications/pc_hall_of_fame/display.c#L154-L245); [initial/new entry cry:527–555](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/applications/pc_hall_of_fame/display.c#L527-L555).

`open_pc_hall_of_fame_screen` has no script operands: load the extra history block, launch the viewer with it, retain the allocated result in script party-management storage, and pause until the child application finishes. ## 4. Credits construction and playback

The credits use text bank **548** (`TEXT_BANK_END_CREDITS`) from `msgdata/pl_msg`, an `ending` graphics NARC, the system font and a layout table of message ID/Y offset/centered flag. There are 237 layout rows (IDs 0–236); the first two are centered, other scrolling rows are left aligned at x=32. Gaps are authored in absolute Y positions (commonly 21 pixels between lines and larger section gaps), rather than inferred from staff text. The final row is reserved for the final screen: scrolling stops printing at row count minus one, while `GetLastMessageID` supplies that last message to the final screen. No staff names or text are copied into this note. [bank/resources:133–153](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/cutscenes/end_credits/main.c#L133-L153); [layout:25–42](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/cutscenes/end_credits/strings.c#L25-L42); [layout tail:247–267](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/cutscenes/end_credits/strings.c#L247-L267); [print limit:323–350](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/cutscenes/end_credits/strings.c#L323-L350); [last row:397–400](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/cutscenes/end_credits/strings.c#L397-L400).

Two managers scroll one continuous layout across the displays at **1 pixel per application update = 30 pixels/second**. Initial top positions are −240 and −448 (192 pixels +16 gap apart); window masks hide 24-pixel edge strips at the inter-screen edges. A 256-pixel tile window is reused circularly: print on entry at the lower edge, erase after the line passes the upper edge, update Y modulo 256. This is text over animated scenes throughout, not a series of static staff pages. [dual managers/masks:152–162](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/cutscenes/end_credits/main.c#L152-L162); [scroll call:186–193](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/cutscenes/end_credits/main.c#L186-L193); [scrolling/erasure:316–395](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/cutscenes/end_credits/strings.c#L316-L395).

The scene order is morning bicycle → memories 1 → day bicycle → memories 2 → night bicycle → Twinleaf → final text screen. Each scene has explicit load/run/unload functions. Bicycle scenes combine player/scarf and Pokémon/object **2D sprites**, scrolling tiled backgrounds and roadside **3D models**, with time-specific lighting. **Music synchronization:** `SEQ_BLD_ENDING_sseq` starts once at application initialization, sound scene 14. Scene milestones and scroll speed share the application's global frame counter; they do not poll a musical beat, sequencer position or audio completion. Thus their sync is authored timeline alignment with the single track. The end condition is scene completion, not “music finished” or `creditsScrollDone`; the latter is assigned by the text managers but does not gate the main scene state machine. Browser implementation must keep that deterministic timeline while audio plays; exact audible alignment remains unverified without an authorized ROM run. **Skipping:** the first completion's staff roll is unskippable because `gameCompleted` was captured **before** setting the flag. On subsequent completions, a newly pressed Start before the final scene initiates a 6f black fade, unloads the active scene, cancels an outstanding brightness transition, frees the scrolling resources and jumps to the final text scene. It does not immediately reset. Once that final scene fades in, A or Start can end it; B/touch are not exit controls here. The global frame counter is not reset on skip, so an early skip can leave the final screen awaiting input until the normal absolute timeout. ## Review notes (2026-10-15)

- **One screen.** The DS credits scroll across both displays (two scroll managers, 24 px edge masks) and the Hall of Fame record screen uses the main screen only. OpenSinnoh never splits the DS layout (`docs/scope.md`): the engine composes the credits as one continuous scroll surface (the two DS displays stacked as one tall view, the edge masks dropped) and the record screen as one capped, centred screen like the other DS-screen menus. Timings stay per DS frame.
- **Opcodes:** `ClearGame` 0xB0; `OpenPCHallOfFameScreen` 0xB1 (postgame PC); `PlayHallOfFameHealingAnimation` 0x25A (party-count var); `GetLeagueVictories` 0x28F; `CheckIsHallOfFameCorrupted` 0x336 (dest var; returns FALSE; the PC's corruption branch depends on it).
- **Import vs constants.** The 237-row credits layout is overlay data: the importer locates it by ROM hash. The scene timings (1830, 4815, 6000, 7980, 10080 …) are code immediates: behavioural constants in our engine, cited to the decomp.
- **Save:** the Hall of Fame history is a new GameState block (version bump with a migration to empty), next to the existing `records.hallOfFame` debut-date semantics.
