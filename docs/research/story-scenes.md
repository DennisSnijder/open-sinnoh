## Timing and wait conventions

All timings below are nominal **30 Hz simulation frames**: 30 frames = 1 second. Preserve each native counter, transition and comparison, including whether a state falls through or returns before its next update. The normal main loop runs the application and main tasks, conditionally waits a VBlank when work has not already spanned one, then always waits another VBlank; the VBlank interrupt increments that counter. Thus ordinary field/application/main-task counters are nominal 30 Hz, not numbers to halve indiscriminately. Interrupt/VBlank callbacks and sound-time units must be considered separately. Slow loads, overrun, animation endpoints, message printers, input and audio completion make total elapsed scene length variable; a timer threshold is not the total scene duration. No ROM timing capture was performed. [Main loop](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/main.c#L121-L160), [VBlank counter](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/system.c#L35-L40).

A native command returning TRUE can mean a **single interpreter yield**, a nested field task, or a script callback wait. It does not establish which of those is in use. Field task completion can immediately unwind to its parent within one update; do not add a frame for every function call. The tables below identify the actual wait predicate. Animation durations whose frame counts live in assets remain data-dependent; importer metadata must supply them. [Field task stack execution](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/field_task.c#L64-L88), [field/application execution](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/field_system.c#L205-L230).

## Engine boundary and common acceptance gate

The baseline already exposes `FieldHost` camera targets/offsets, actor movement, warps, sound, elevator and platform-lift tasks. `FieldView` has camera target/offset, actors, effects, elevator lights, platform lift and dynamic feature models/fog; `Prop.animations` has clip IDs and 30 Hz lengths. It does **not** yet provide all scene-specific application views, independent prop channel controls, full camera/frustum tracks, layered brightness/masks, or Safari/temporary-map lifecycle state described here. Names for proposed services below are illustrative contract requests, not APIs this note adds. [Contracts](../contracts.md), [FieldHost](../../packages/contracts/src/field.ts), [FieldView](../../packages/contracts/src/runtime.ts), [prop/animation records](../../packages/contracts/src/records.ts).

- World owns deterministic scene tasks, resource lifetimes, completion signals and movement/input locks. VM resolves operands, calls a typed `FieldHost` service and follows the native wait/poll contract. Standalone scenes need a headless application model plus renderer view; completion must never depend on WebGL or an audio device being available.
- A scene view needs only the scene's active models/props and their clip/channel/frame/transform state, sprite layers, camera target/angles/distance/FOV/clipping, light/fog override, and fade/brightness/mask state. Extend existing surfaces where sufficient; do not invent a generic cinematic language before the first scene works. Audio must preserve scene-bank selection, cues, fades and completion semantics through the existing audio host. Native main/sub-screen effects describe source behavior; adapt them to the project's single main view and overlay card, preserving the authored framing rather than adding a second DS surface.
- Import resources from the user's verified ROM into engine-neutral records. Preserve member identity, clip length/loop policy and skeletal/material/texture tracks, 2D resource palettes and layer ordering, particle definitions where used, camera/light tables and sound dependencies. Imported output changes require `IMPORTER_VERSION` to increase. No binary assets or converted outputs belong in git.
- Each proposed `sys-*` replay below must run headless twice on seeds 1–3, with +1/+2/+5/+15 delayed starts and a save round trip at idle **before and after** the scene. Saving mid-task remains prohibited by the current contract; reconstruct only supported persistent idle states. Assert no relevant stub, task leak, stale temporary map, input lock, camera/brightness override or stray sound after cleanup. Never use a blind time advance as proof of completion.
- Add original fixture models/clips/palettes and task tests for timing/endpoints/input edges; ROM replays use `romSlice()`, browser tests use `seedRomImport(page)`. Browser desktop/phone checks should inspect at least one intermediate beat per scene and cleanup, without committing ROM screenshots. Replay names below are proposals, not implemented or passing tests; new scene-state assertions may need bridge/contract support. Keep CP11/14/15/16 progression assertions in their checkpoint chains as well as isolated system coverage.

## Boat travel — CP11 (`play_boat_cutscene`)

**Dispatch and ownership.** The command reads literal direction/exit bytes, destination map and x/z halfwords; it pushes a nested field task, so script continuation waits for the complete journey. `FieldSystem_PlayBoatCutscene` owns departure/bridge/fades/map changes; a child application in overlay `cutscenes` owns the ship cinematic (`BoatCutscene_CanalaveShip_*`). Direction 3 is the Canalave departure; direction 0 returns. CP11 sails to Iron Island `(100,502)`, east facing, and returns to Canalave `(44,750)`, west facing. The scripts first walk and hide the sailor/player, with `SEQ_SE_DP_KAIDAN2_sseq`; player choice is before task launch. The cinematic does not poll cancel/skip input. [Opcode](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/scrcmd.c#L5553-L5563), [application binding](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/unk_0203D1B8.c#L1439-L1451), [departure script](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/res/field/scripts/scripts_canalave_city.s#L523-L589), [return script](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/res/field/scripts/scripts_iron_island.s#L15-L35), [direction/destination macros](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/asm/macros/scrcmd.inc#L3379-L3401).

**State machine and timing (30 Hz).** Initialization selects sound subscene 64 with `SEQ_NONE`, loading its sound resources without starting or stopping a BGM track; the explicit BGM fade comes later. Canalave outward finds `regular_ship_nsbmd` near the player, copies the player's world position into a detached camera target, loads both bridge halves and starts `SEQ_SE_DP_SHIP02_sseq`. Return trips skip field-prop departure and begin at fade-out. Departure starts at speed 0.25 world units/update; on update 24 it adds **1**, becoming 1.25 (not 1.0). Position is moved before that increment, while the accumulated distance uses the incremented speed. The outward goal is 25 tiles (400 units), bridge trigger 14 tiles (224 units). **Derived arithmetic:** bridge animation starts on departure update 198; goal predicate first succeeds on update 339. The helper's parameter names are misleading, but its caller reverses them, implementing accumulated distance >= bridge distance. Continue moving until both bridge one-shots have ended **and** the goal predicate holds; 339 is therefore a minimum, not an unconditional departure duration. The camera target follows the boat's negative-z travel and pans +x by 1 for 32 updates (two tiles). [Initialization](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/cutscenes/boat_cutscene/boat_cutscene.c#L74-L142), [departure and waits](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/cutscenes/boat_cutscene/boat_cutscene.c#L182-L222), [movement/bridge/pan](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/cutscenes/boat_cutscene/boat_cutscene.c#L250-L364).

Next: start both-screen black fade and BGM fade (each parameter 6); wait for both; unload bridge one-shots; finish the field map; run the child application and wait until it exits; change map with warp ID -1 and supplied coordinates/facing; start destination BGM and map/fade-in; free the task. The cinematic initializes a fixed camera, starts its six-step brightness-in fade, plays `SEQ_SE_DP_SHIP01_sseq` on its first main callback and advances four attached animations by one source animation frame each callback, clamped at their final frames. When animation channel 0 reaches its last frame, start the six-step fade-out; exit only after fade completion. **Unknown duration:** animation-frame totals live in the archive assets and were not measured; preserve the channel-0 completion predicate rather than inventing an overall duration. A fade parameter is a transition count, and task/application initialization adds scheduling boundaries; do not add these numbers and claim an exact whole-journey frame count. [Parent and child task transitions](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/cutscenes/boat_cutscene/boat_cutscene.c#L144-L248), [cinematic main](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/cutscenes/boat_cutscene/canalave_ship.c#L84-L189), [fade helper](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/unk_0208C098.c#L80-L87).

## Explosion shake and Canalave library television — CP9 / CP11

**Do not conflate scenes.** `scr_cmd_29f` itself neither explodes a lake model nor changes the story flag: it selects one of two overlay006 camera-shake field tasks. Pastoria's Great Marsh bomb and Canalave's report of Lake Valor both use operand 1. The library script writes the exploded/cameramen flags only after the complete conversation/TV/exit sequence. [Dispatch](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/scrcmd.c#L6374-L6385), [Pastoria scene](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/res/field/scripts/scripts_pastoria_city.s#L642-L666), [library sequence and end flags](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/res/field/scripts/scripts_canalave_library_3f.s#L118-L192).

**Shake variants: phases, camera, audio.** Both clone the current camera, track a temporary target and make it active, leaving the original target available for restoration. Movement is x-only; y amplitude is zero. Each cycle is four callbacks: target +amplitude, zero, -amplitude, zero (one-step interpolation on each leg). Mode 0 begins with amplitude 2 units and 16 cycles: 64 shake callbacks followed by one camera-restore callback; its wrapper then frees the helper on the next field-task callback. Both variants play `SEQ_SE_DP_CLIMAX09_sseq` during helper initialization, before the first field-task update. Nonzero mode begins at amplitude 4 and 24 cycles. After each cycle it subtracts the fixed-point quotient amplitude/8 from the amplitude; this approximates 7/8 decay, but a direct rounded multiply need not give identical values. Its first task update requests BGM fade-out parameter 1, waits for audio fade completion, delays 16 callbacks and plays `SEQ_SE_DP_FW089_sseq`; then 96 shake callbacks plus the restore callback; stops effect numeric ID 1628; waits another 16 callbacks; requests BGM fade-in to volume 127 with fade parameter 16 and FROM_ZERO; waits for audio completion and frees the task. State transitions/polling add boundaries, so the meaningful exact counts are phase counts, not an invented 145-frame total. The complete nested task blocks the calling script, with no skip input. The BGM completion counter is decremented once per `SoundSystem_Tick`, except while a fanfare is playing; the actual volume ramp is separately handed to the sound player. Do not equate audible fade duration with task-counter duration. [Audio fade requests/poll](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/sound_playback.c#L158-L198), [counter update](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/sound_system.c#L51-L81), [volume ramp](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/sound.c#L576-L579). No models, particles, texture animation or palette effect is loaded by either helper; the explosion is conveyed by camera/audio and surrounding script. [Mode 0](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/overlay006/ov6_0223E140.c#L498-L530), [nonzero timeline and decay](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/overlay006/ov6_0223E140.c#L532-L619), [interpolation](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/overlay006/ov6_0223E140.c#L1713-L1742), [camera lifecycle/cycles](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/overlay006/ov6_0223E140.c#L1819-L1962).

**Library camera/script envelope.** Lock control; move rival/player to table; add free camera at player x/z and move three slow steps east; delay 30, later delay 10; run NPC turns and player-advanced conversation. At the explosion beat, wait on confirm SE, print instant text, run nonzero shake; walk rival toward TV/player face north; fade out, wait, restore field camera; run `start_library_tv`; explicitly `ReturnToField`; reconstruct free camera and repeat east move; fade in; later delay 15; NPCs leave while camera moves three slow steps west; wait for all movements, remove NPCs and restore camera. Slow walk is 16 movement updates per tile, so each authored three-tile pan has 48 movement updates, plus movement command scheduling. City state 5 belongs to the subsequent outside scene, not TV-app completion. ## Galactic HQ warp panels and guardian containment (CP14)

### Warp panels: a tile-triggered map transition

**Owner and wait.** Overlay 5 field input identifies a warp-panel tile and delegates to the core `FieldTask_MapChangeWarp`, which launches overlay 5's `FieldSystem_StartWarpAnimation` twice. There is no dedicated HQ script opcode or player confirmation: stepping onto the event starts a field task, and ordinary field input is suppressed while it runs. The destination is the event's map/header and zero-based warp index, with current facing supplied initially. Example: HQ3F warp 4 at (15,13) leads to warp 3 at (6,14) in the same room; HQ4F warp 1 at (22,3) leads to laboratory warp 0. Preserve same-map transitions and destination-warp resolution. [Dispatch](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/overlay005/field_control.c#L813-L823), [task and initial location](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/field_map_change.c#L1020-L1078), [input gate](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/field_system.c#L233-L238), [HQ3F events](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/res/field/events/events_galactic_hq_3f.json#L197-L227), [HQ4F event](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/res/field/events/events_galactic_hq_4f.json#L105-L117).

| Phase | Nominal 30 Hz timing and completion |
|---|---|
| Depart | Play `SEQ_SE_DP_TELE2_sseq`; rotate facing on odd updates in north → west → south → east order. Raise the sprite with quadratic vertical displacement, using counter values starting at 0. At counter 20 begin a black brightness fade of duration 6. Continue rising until counter >20 **and** fade finished. This is roughly 26 updates, not an unconditional fixed 20-frame delay. |
| Swap | On departure completion, try the destination BGM fade, finish field map, load the destination event location, wait for audio fade, start BGM and restart map. Loader/audio dependent; no fixed total. |
| Arrive | Draw player with the reverse height profile (initial counter complement 20), play the same teleport sound, rotate on odd updates. Counter 2 begins brightness fade-in duration 6; after counter >20, wait for fade completion and face south. Clear task only afterward. |

The animation owns sprite offset and facing, not a moving world camera; do not move the player's collision coordinate upward. The task's cleanup and renderer-visible offset reset must agree on arrival. These are ordinary avatar graphics and field geometry, with a brightness fade, not a newly loaded model, SPL particle archive or palette-cycling application. There is no separate panel effect resource loaded by this animation. [Departure and facing sequence](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/overlay005/ov5_021E135C.c#L28-L79), [arrival and task creation](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/overlay005/ov5_021E135C.c#L81-L145), [map/BGM phases](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/field_map_change.c#L1026-L1066).

**Engine work (proposal).** Retain imported warp-event pairs and tile behavior; add a world-owned warp transition style to the existing warp service, with a start/completion seam and an avatar sprite-height/facing track in `FieldView`. Field input, collision position, map load hooks and BGM must remain synchronized. Importer needs no HQ-specific route hardcoding: tile behavior plus events, ordinary map resources, avatar sprite and teleport sound suffice. Assert south facing at completion rather than preserving entry facing accidentally. The duration is phase-based, including loader/fade completion, not a single timer.
