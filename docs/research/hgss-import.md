# HGSS US import: optional followers first, a second base pack later

Research date: 2026-10-16. Scope: HeartGold/SoulSilver as a second base pack (`ROADMAP.md`) and the 2026-10-15 following-Pokémon decision. This is an implementation plan, **not a claim of HGSS support**. The only repository addition is this note.

HGSS references below are pinned to `ctrl-cheeb-del/pokeheartgold` commit `3cbb8782eb8dbef62fc9dbe3e5b87313a8116331`. The repository has no licence; use its names, locations and understanding, independently implement the readers and behavior, and copy no source, assets, game text or game data tables. Detection should use our existing header reader: game code at `0x0C`, maker at `0x10`, revision byte at `0x1E`, then **whole-file SHA-1 allowlist**. Code/revision alone are diagnostic, not acceptance: patched, trimmed, translated or corrupt inputs must not reach fixed-offset readers. Add edition-specific identity descriptors and dispatch; adding HGSS hashes to `SUPPORTED_ROMS` alone would let Platinum-shaped logic proceed too far. Measured HG: 134,217,728 bytes, `IPKE`, revision 0, matching the hash above. This confirms this particular input, not arbitrary `IPKE` files.

### NitroFS and path/name mapping

FNT/FAT and NARC containers are the same families. HGSS strips many descriptive filenames into `/a/X/Y/Z`; numeric NARC IDs are **not FAT file IDs**. Resolve runtime paths from the ROM FNT, and NARC members from BTAF. `filesystem.mk` explicitly describes stripping and maps logical build paths to runtime paths; `sNarcFileList` is the runtime authority. [filesystem.mk:387–418](https://github.com/ctrl-cheeb-del/pokeheartgold/blob/3cbb8782eb8dbef62fc9dbe3e5b87313a8116331/filesystem.mk#L387-L418); [include/filesystem_files_def.h:6–88](https://github.com/ctrl-cheeb-del/pokeheartgold/blob/3cbb8782eb8dbef62fc9dbe3e5b87313a8116331/include/filesystem_files_def.h#L6-L88); [include/filesystem_files_def.h:275–360](https://github.com/ctrl-cheeb-del/pokeheartgold/blob/3cbb8782eb8dbef62fc9dbe3e5b87313a8116331/include/filesystem_files_def.h#L275-L360).

### ARM9, overlays, locations and compression

**New prerequisite:** executable decompression. Measured HG has **127 compressed ARM9 overlays out of 129**. `NitroFs.overlay()` currently rejects compression and `arm9()` returns on-disk bytes. HGSS builds compressed ARM9 and overlay components (`main.sbin_LZ`, compressed definitions/table); add independently implemented Nitro backward decompression, separately from our existing forward LZ10/LZ11 asset handling. Use header overlay entries to map overlay ID → FAT ID → stored bytes; use the decompressed RAM address for pointers. The build's compression step and ROM component declarations corroborate the requirement. [Makefile:88–120](https://github.com/ctrl-cheeb-del/pokeheartgold/blob/3cbb8782eb8dbef62fc9dbe3e5b87313a8116331/Makefile#L88-L120); [rom.rsf:1–14](https://github.com/ctrl-cheeb-del/pokeheartgold/blob/3cbb8782eb8dbef62fc9dbe3e5b87313a8116331/rom.rsf#L1-L14). Exact ARM9 footer/module-parameter interpretation in our own reader is an implementation spike; the in-memory research decompression below does not implement it.

## 2. Platinum importer family compatibility

“Same” below means the wire family/schema can be reused with boundary tests. It does not mean the current Platinum orchestration, member indexes, names file or game semantics can be reused unchanged.

### Maps, matrices, zones and events: mixed; important changes

- **Matrix: same schema.** Width/height, optional zone-header/altitude sections, length-prefixed name, then u16 chunk IDs. Reuse `readMapMatrix`, validate limits and sentinels. [src/map_matrix.c:31–58](https://github.com/ctrl-cheeb-del/pokeheartgold/blob/3cbb8782eb8dbef62fc9dbe3e5b87313a8116331/src/map_matrix.c#L31-L58).
- **Land wrapper: changed.** Four u32 section lengths remain at offset 0, followed at offset 16 by a **u32 soundplate header**, whose high 16 bits give the extra payload byte length. Permissions begin at `20 + soundplatePayloadLength`, followed by props, model, BDHC. Our Platinum reader assumes offset 16 and exact `16 + section sizes`, so needs a separate adapter. Soundplate header bits/payload meaning remain a full-base-pack research item; preserve validated structure without silently discarding behavior. [src/field/map_load_manager.c:389–403](https://github.com/ctrl-cheeb-del/pokeheartgold/blob/3cbb8782eb8dbef62fc9dbe3e5b87313a8116331/src/field/map_load_manager.c#L389-L403); [src/field/map_load_manager.c:426–433](https://github.com/ctrl-cheeb-del/pokeheartgold/blob/3cbb8782eb8dbef62fc9dbe3e5b87313a8116331/src/field/map_load_manager.c#L426-L433); [src/field/map_load_manager.c:503–511](https://github.com/ctrl-cheeb-del/pokeheartgold/blob/3cbb8782eb8dbef62fc9dbe3e5b87313a8116331/src/field/map_load_manager.c#L503-L511).

### Lifecycle, movement and hiding

Use a party Pokémon follower separate from the existing story-partner actor. Spawn from the first alive non-egg; on initial creation, if none are alive, HGSS uses the first non-egg. On lead identity/reorder/form/gender/shiny change, refresh sprite/parameters/mood; if the required map object does not exist, request recreation rather than leaving a stale actor. [src/follow_mon.c:1508–1635](https://github.com/ctrl-cheeb-del/pokeheartgold/blob/3cbb8782eb8dbef62fc9dbe3e5b87313a8116331/src/follow_mon.c#L1508-L1635); render-resume checks [src/field/map_object_billboard_motion.c:346–387](https://github.com/ctrl-cheeb-del/pokeheartgold/blob/3cbb8782eb8dbef62fc9dbe3e5b87313a8116331/src/field/map_object_billboard_motion.c#L346-L387). Empty/egg-only party handling needs an explicit boundary test; do not call a “crash if none” helper blindly in our engine.

Movement is a queue/state machine over the **player's previous tile**, direction and movement speed. Preserve ordering through queued steps and waits. It selects faster movement when catching up; pending ledge actions use the hop state rather than teleporting across the ledge. A hop runs its held movement twice (two completed segments), and vertical/bob behavior is affected by shape. The catch-up helper promotes slow directional actions (8–11) → step (12–15) → run (16–19) → fast (20–23), preserving the requested direction. The queued-step state progresses 1→2 before starting a step, then 3→0 when consumed; a new queued player step can replace that pending state. A pending hop chooses one faster action, resets hop count/frame, and runs two movement segments; a regular step uses the player's speed toward their previous tile. Player actions 56–59 are handled specially to establish the pending hop rather than interpreted as ordinary walking. Situation construction has details that generic proximity code would miss: NPC count is in the player's 3×3 neighborhood excluding IDs `0xFD/0xFF`, but rock/tree flags scan all active objects; hidden items count all uncollected hidden events in the map. Weather codes are sunny=1, rain=3, other=0. Terrain is sampled beneath the **follower**, and encounter-tile is 1 for encounter terrain, 2 otherwise. Time codes are morning/day/evening/night/late=1..5. Facing codes are east/west/north/south=1/2/3/4. HP buckets are full/≥75%/≥50%/≥25%/less (integer percentage). Mood predicate codes 1–8 mean exactly 127, 100–126, 50–99, 30–49, −29–29, −49–−30, −126–−50, exactly −127; 9 means nonnegative, 10 negative. ### Interaction steps, motions, messages and mood

Movement `0xFFFF` terminates the list, at most five steps. Trailer: u32 ask-question, u16 yes-script, u16 no-script, s8 friendship delta, s8 mood delta, u8 accessory+1, u8 Shiny Leaf. Validate lengths/references and convert to a small typed interaction IR; never send it to the field-bytecode decoder.
