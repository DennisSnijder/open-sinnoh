# Underground and Super Contests: scope check

2026-10-16. Scope report for the Underground and Contests; no implementation or scope decision is made here.

**Recommendation:** implement the single-player Underground and the complete NPC Super Contest circuit after M5 and postgame essentials. Keep multiplayer as a separately costed decision. `docs/decisions.md` (2026-10-14) already keeps both systems in scope at last priority; permanent omission would change that decision. `docs/scope.md` also excludes wireless/online features. “Full” below deliberately includes the original local-wireless experience so its additional scope is visible; it does not imply that wireless is in scope.

Source: [pret/pokeplatinum at `1dc13dcea40c04ab53f1f607de46023dc409ef20`](https://github.com/pret/pokeplatinum/tree/1dc13dcea40c04ab53f1f607de46023dc409ef20). This is the inspected revision for every decomp path and count below. References are for names, data locations and understanding only: no copied code, assets, dialogue or ROM-derived material. Links pin the revision; bare paths in count tables are relative to that source tree. This is a static dependency audit, not a hardware/wireless playthrough.

Read alongside `docs/scope.md`, `docs/decisions.md`, STATUS.md, `docs/contracts.md` and research notes `story-cp5-19.md`, `menus-and-services.md`, `berries-honey-radar.md`, `poketch.md` and `move-animations.md`. The engine already supplies the field, bag, party, Pokémon/ribbons, apps, deterministic 30 Hz ticks, clock, saves, audio and ROM format decoders. It does not thereby supply either minigame. Its UI is **one composed screen**: the former DS touch content becomes controls/cards within the active scene, never a second DS panel beside or below it.

## 2. Super Contests

### Activities and offline/link boundary

- Five categories (Cool, Beauty, Cute, Smart, Tough), four ranks (Normal, Great, Ultra, Master), four entrants, three judges. Offline official mode supplies NPC rivals; local link mode is separate; practice can run individual visual/dance/acting competitions. Constants: [include/constants/contests.h:4](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/include/constants/contests.h#L4); ranks: [generated/pokemon_contest_ranks.txt:1](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/generated/pokemon_contest_ranks.txt#L1); script receptionists: [res/field/scripts/scripts_contests.s:21](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/res/field/scripts/scripts_contests.s#L21). All three rounds are genuine solo content; none needs wireless to function.
- Visual: timed Pokémon dress-up using owned Fashion Case accessories, a category/theme assessment and a backdrop. Rank limits accessory count (5/10/15/20), with a 60-second setup visible in overlay22. Condition is assessed separately from dress-up and converted through rank-specific thresholds. Backdrops support presentation rather than a separate gameplay round. Sources: [src/overlay022/ov22_02255D44.c:935](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/overlay022/ov22_02255D44.c#L935), `:1450`; [src/overlay017/ov17_0223F118.c:193](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/overlay017/ov17_0223F118.c#L193) (accessory scoring), `:206` (condition); [src/unk_02094EDC.c:932](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/unk_02094EDC.c#L932) (condition and accessory threshold transforms); [src/overlay017/ov17_02252A70.c:10](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/overlay017/ov17_02252A70.c#L10) (accessory-data calculation).

This is a summary of factual mechanics, not a proposed code port. [src/applications/poffin_case/main.c:469](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/src/applications/poffin_case/main.c#L469); party and summary feeding modes are used by this application (`:289`, `:326`). ## 3. Integration and acceptance boundaries

- **Contracts and saves:** propose typed Underground state/tables/views and Contest session/rules/results/Fashion Case/Poffin/condition state through `@opensinnoh/contracts` and `@opensinnoh/core`. Packages must not import one another's internals. Current Pokémon ribbons and move `contest {effect,type}` metadata are useful seams, not complete rules. Pokémon condition and Beauty evolution are currently absent (`packages/core/src/pokemon.ts`); summary Contest pages are deferred (`packages/menus/src/summary.ts`). Pick the numeric schema version at merge. Cartridge-save import must explicitly preserve or report unsupported new fields; the existing menus/services note excludes Underground cartridge state.
- **Importer:** unpack only assets and tables needed for the chosen scope from the user's ROM; recover remaining opaque Contest record schemas before estimating them as done. Any changed output needs an `IMPORTER_VERSION` bump. No ROM/extracted assets, copied decomp tables, dialogue or screenshots in git. Resource paths here identify import work, not distributable material.
- **Timing and input:** seeded RNG and 30 Hz serializable logic; sphere growth uses the engine clock. Dance needs a proven mapping between beat timing, timestamped input and the existing audio scheduler; do not base scoring on rendering frame rate. Visual editing, trap escape and cooking need keyboard and touch within the same composition. Move animations already skip some Contest-specific paths; audit the animation bridge rather than assuming battle coverage proves Contest coverage.
- **Prove scope:** original fixtures for mining collapse/rewards, sphere growth and overflow, base collision/rank restrictions, trap escape; NPC Contest round scores/ties/AI, rank eligibility, reward idempotency, Poffin saturation/sheen/nature and Beauty evolution. Save/reload permanent state; make the policy for leaving/saving during active minigames explicit. ROM-gated tests should use shared `romSlice()`/`seedRomImport(page)` except importer tests. Run only affected browser specs while working, then the normal merge gate.
- **Preserve progression:** replays must show kit receipt without going underground clears Eterna, and Hall arrival plus Fantina dialogue without a Contest clears the gym gate. Hall-visited also enables the Pokémon comparison menu ([res/field/scripts/scripts_common.s:989](https://github.com/pret/pokeplatinum/blob/1dc13dcea40c04ab53f1f607de46023dc409ef20/res/field/scripts/scripts_common.s#L989)), so retaining only Fantina's flag is insufficient. No audited badge/Champion/National Dex/Stark Mountain route requires winning either minigame; the optional dependencies listed above remain visible instead of being called story blockers.

The current scope decision already covers the offline work. The choices requiring an explicit scope decision are permanent omission, enabling multiplayer despite the wireless exclusion, or invented solo replacements for multiplayer rewards.

## 4. Options and recommendation

These are order-of-magnitude **new TypeScript lines**, including importer/data readers, gameplay, composed UI, migrations and focused original-fixture/unit/replay/browser tests. They exclude ROM assets, generated data volume and generic engine work already present. They are independent implementation estimates, not C-to-TypeScript conversion ratios. Uncertainty is roughly ±50%, greater for networking and opaque Contest data. A work stream is a bounded implementation responsibility against contracts, not a person-week.

For calibration, the current Pokétch model's seven files plus its app renderer total 2,545 TS lines, while these systems add spatial editing, persistent economies or three competing minigames. These estimates allow substantially more than a menu application. They should be revised after a mining-board prototype and a full NPC Contest replay prove the data and timing assumptions.
