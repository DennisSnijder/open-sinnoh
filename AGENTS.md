# Contributing to OpenSinnoh

This guide is for everyone who changes the code, people and AI coding assistants alike. Read
`docs/scope.md` (scope, hard rules), `docs/decisions.md` (design decisions and why), `STATUS.md`,
`docs/contracts.md`, and the notes in `docs/research/` for the area you work on.

- **Hard rules.** Never commit a ROM, anything extracted or derived from it, or screenshots of ROM
  content (the one exception is the curated landing-page media in `site/shots/` and the site's link card,
  `site/public/og-image.png`). ROM tests read `OPENSINNOH_NDS_ROM` and skip without it. All other tests use
  original fixtures (`packs/fixture`, or bytes generated by our own writers in tests).
- **References.** `reference-projects/` is a gitignored, local-only checkout of reference material (the
  pret decompilations); it is never committed. The decompilations have no licence: use them for names,
  offsets and understanding, and copy no code or assets. Read code closely only from permissively licensed
  tools (apicula, NitroPaint, nitrogfx, VGMTrans); copy from none. Credit new sources in `CREDITS.md`.
- **Style.** Prove first, harden second. Keep it simple: no speculative abstraction, no defensive code
  for impossible states, no silent fallbacks. Fail loudly on unexpected internal states. Validate
  strictly only at boundaries (ROM, packs, saves, user input). Unimplemented script commands log once
  and are counted in coverage. They never crash, and they never pass silently.
- **OpenSinnoh's own UI.** Building or changing an OpenSinnoh-owned screen (Options, setup, crash, data, mods)
  or website/brand work follows the design system: `docs/design-system.md` (and the `opensinnoh-ui` skill in
  `.claude/skills/opensinnoh-ui/SKILL.md` for AI assistants).
- **Importer output.** Any change to what the importer writes (records, assets, file layout) must bump
  `IMPORTER_VERSION` in `packages/app/src/importer.ts`, or browsers keep a stale cached import.
- **Stored names.** Some strings predate the project's name and are stored in players' browsers and files:
  the `lantern-nds:*` localStorage keys, the `lantern-nds` and `lantern-nds-saves` databases, the save format
  `lantern-nds-save`, glTF `extras.lantern` and the `Lantern_*` text ids. Never rename them without a tested
  migration.
- **Packages.** Packages depend on `@opensinnoh/contracts` and `@opensinnoh/core`, not on each other's
  internals. A contract change bumps `CONTRACTS_VERSION` and gets a line in `docs/contracts.md`.
- **Dependencies.** A new runtime dependency (anything bundled into the game or the site) needs its licence
  notice in `THIRD_PARTY_NOTICES.md`.
- **Checks.** `pnpm check` (lint, typecheck, unit tests and pack replays, in parallel) must pass. With a ROM,
  run the ROM tests too: `OPENSINNOH_NDS_ROM="/path/to/platinum.nds" pnpm test`. Report real results.
  - **Fast tier, while you work:** `pnpm test:changed` (tests touched by your diff against `main`; add the
    ROM variable for ROM tests), or `pnpm vitest run <file>`, and the browser specs your change touches
    (`pnpm test:browser tests/browser/<spec>`, or `pnpm test:browser:changed`).
  - **Full tier, before merging:** `pnpm check`, ROM `pnpm test` and the full ROM `pnpm test:browser`.
  - **ROM tests share one import.** Use `romSlice()` from `tests/rom.ts` (the `{ slice: true }` import, made
    once per run and cached in `.opensinnoh-cache/tests`, keyed by ROM SHA-1, `IMPORTER_VERSION` and the
    importer's sources). Browser specs that need the imported game but do not test the import call
    `seedRomImport(page)` (`tests/browser/seed.ts`). Call `importPlatinum` directly only to test the importer.
  - **Spread long ROM work over files:** vitest runs files in parallel and the tests in a file in order.
- **Docs.** `STATUS.md` stays a short current-state page, `ROADMAP.md` lists what's done and next, and
  `docs/decisions.md` gets a short bullet under its topic for each decision worth explaining. No logs, no
  ceremony.
- **Merging main.** Merge main into a branch with `git fetch && pnpm merge:main` (not a plain
  `git merge origin/main`). It commits the merge when only `CONTRACTS_VERSION` or `IMPORTER_VERSION`
  conflict (when both sides bumped, the result is one past the larger: a patch bump for contracts; raise it
  to a minor bump by hand if the merge needs one), and otherwise leaves git's normal conflicts to resolve.
  `docs/contracts.md` is not handled: put both changelog lines under the merged version by hand.
